## 3. 同一次更新：参考点究竟与什么冲突

使用每个最终提交 trial 的同一组 x−、P−、H、v、R、x+、P+。RTKLIB H 是 nx×nv 列主序，观测雅可比为 Hᵀ。

不重新线性化、不改权，条件后验均值严格计算为：

```
d = reference_position - xplus_position
x_cond = xplus + Pplus[:,position] * solve(Pplus[position,position],d)
```

检查目标函数 `dxᵀ(P−)⁻¹dx + (v−Hᵀdx)ᵀR⁻¹(v−Hᵀdx)`，其条件化增加量与 `dᵀ(Pplus_position)⁻¹d` 一致。使用直接求解，无伪逆、正则化或参数替换。

### 实际更新预算

### 消去不可直接固定的状态

另外仅作离线单历元解释：固定位置，保留全部实际观测及 IONO/TROP 虚拟行和 R，去掉目标函数中的时间预测惩罚，使用白化、列归一化、满秩 QR 消去钟差/ISB、RCB、逐星 I 和模糊度。没有删卫星或观测行；启动 gauge 未满秩时不求解。

设白化后的其余状态设计阵为 A，QR 正交基为 Q，ZTD 列为 a：

```
a_perp = (I - Q Qᵀ) a
delta_ZTD = a_perpᵀ y / (a_perpᵀ a_perp)
```

自由轨迹保存矩阵在参考点的单历元最优总 ZTD：59/129/160/179/299/477 序号分别约为 3.992/4.533/5.359/6.802/4.957/6.975 m。但对应 ZTD 单历元形式标准差约 2.31～2.44 m。**这些不是可靠大气估计，更不是替代连续 PPP 的方法。**

末点自由矩阵的总 ZTD 高于预报 4.614293 m，其有符号剖面分数：码行合计 +5.126298 m、IONO 行 −0.512005 m；相位和 TROP 行分数约零。相位的零分数来自此单历元拟合允许各模糊度自由吸收，不代表相位在完整回放中无作用；TROP 行恰在预报中心，右端为零，其信息仍在分母中。

若按行标识列举其中较大的有符号分数：C36 2I +2.2002、G26 1C +1.9310、C12 2I +1.4225、G16 1C +1.1758 m；C06 2I −0.9469、G04 1C −0.9184 m。**这些是特定线性化与联合状态投影下的分数，不能叫作各卫星原始误差或删除效应，也不是屏蔽建议。** 完整行表在 `trop_profile_rows.csv`。

从独立固定轨迹矩阵得到末点单历元总 ZTD 5.5627 m、标准差 2.5996 m，仍偏向异常大湿延迟，但值不同，因为全程历史已改变既有权重/编辑。未用两者差值冒充单因素因果效应。

## 5. 已排除与未证明事项

本轮不能证明：

- 每项物理改正均独立正确。观测分解闭合首先是实现账本核对，不能替代独立物理参考。
- 码方程失配就是原始采集数据坏；状态/先验或未建模接收机与产品参考项仍可产生同样表现。
- GIM/VMF3 产品本身错误，或某个频点/星座应永久排除。
- 形式协方差收紧本身就是代码 bug。实际统计一致性还受相关误差和模型充分性影响。

**下一步最小范围：围绕已保存的固定坐标码方程与电离层/接收机偏差参考，辨认能够独立检验的缺失物理项，再决定是否修改 `corr_meas()`、`model_iono()` 或 `ppp_res()` 对应项。当前没有证据支持给 `udtrop_ppp()` 加下限、改 Q/R 或重置状态来“修复”9 m。** 本轮正式算法修复条件尚未满足。
