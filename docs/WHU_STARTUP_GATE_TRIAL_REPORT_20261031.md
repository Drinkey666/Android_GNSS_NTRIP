# WHU启动门控独立修改与完整回放（2026-10-31）

## 结论

已按用户授权实现独立启动策略并重算最新669历元；不是只画原84期曲线或在原结果前补插值。**首次看到估计推进即可启用：585秒→290秒；首份完整偏差即可启用的诊断组：585秒→5秒。**所有组只使用对应历元原来实际已接收的字节，未使用未来改正。

首份组得到663个PPP解、1个Q5、5个WAIT，末水平1.693m、Up+0.388m，末60期高程RMS0.407m；因此原门控确实挡住了可以进行数值PPP更新的时段。但首份组实际使用的偏差估计年龄最高约910秒，尚无独立有效期认证，不能因此宣称前9分钟都已得到经过产品有效性认证的实时精度。

正式PC EXE、Android源码/原生库/APK、默认策略均未改动、未安装。没有修改R/Q/P0/GIM/抗差/Joseph、信号选择或基于真值调参。实验仅位于`validation/whu_startup_trial_20261031/snapshot/`及独立可执行文件，三个运行环境均清除历史研究环境变量。

## 独立策略和唯一差异

|组|启动资格|备注|
|---|---|---|
|strict_control|该星相邻估计严格相隔300秒|正式策略控制|

控制和候选统一保留：轨钟90秒上限、未来时刻保护、轨钟来源/解/IOD一致性、独立偏差来源/配置锁定、广播IODE/健康/卫星位置及幅值检查、实际信号偏差valid标志和ANTEX参考、接收陈旧90秒、估计不推进300+5秒看门狗、估计倒退拒绝和transport reset。来源或配置改变仍停止会话。未更换挂载点或混入文件SP3/CLK/BIA。

`first_advanced`在接收中断>90秒或transport reset后清除“已见推进”的资格；`first_complete`同样必须重新收到完整偏差。所有组继续应用已有接收/估计时标检查；首份诊断组没有被悄悄加一个新的“允许910秒”参数。

更多时段进入滤波后，状态、协方差、原有质量历史及残差处罚自然不同。因此“R公式和参数未修改”不等于每期有效R数值完全相同，更不要求最终坐标与原策略相同。
